# ADR-007: Canonical Conventions & Source-of-Truth Hierarchy

## Status
Accepted — **Supersedes all conflicting statements** in any other document in this repo.

## Context

During documentation review (see `docs/REVIEW.md`) we found that the spec had drifted:
the same concept was described differently in different docs, and several docs describe
infrastructure that does not yet exist on disk. An autonomous agent (and its sub-agents)
cannot resolve ambiguity by asking the author. Therefore we establish, once and for all:

1. A **strict hierarchy of sources** — when two documents disagree, the higher one wins.
2. A **single canonical convention** for every recurring decision (framework, paths,
   event envelope, naming, errors, testing).
3. An explicit list of **known conflicts already resolved** so the agent does not "re-litigate" them.

This ADR is the contract the building agent codes against. If a doc contradicts this ADR,
the agent follows **this ADR** and opens a PR fixing the doc (see AGENT.md §Conflicts).

## 3. Event Envelope (canonical)

```typescript
// @pmos/shared — EventEnvelope
interface EventEnvelope<T = Record<string, unknown>> {
  id: string;            // UUID v4
  type: string;          // "pmos.notes.created"
  source: string;        // service name, e.g. "notes"
  timestamp: string;     // ISO 8601
  version: number;       // schema version of the event, starts at 1
  correlationId: string;  // UUID, propagated through HTTP + events
  data: T;               // camelCase payload, typed per event
}
```

- `data` fields are **camelCase** everywhere (`noteId`, `bodyMd`, `profileIds`, `taskId`,
  `meetingId`, `projectId`, `fileId`, `externalEventId`, `oldStatus`, `newStatus`).
- Subject = `pmos.` + event type from `contracts/asyncapi/events.yaml`. SAGA.md's
  `notes.created` shorthand == `pmos.notes.created`.

## 4. Error Envelope (canonical)

```typescript
// @pmos/shared — ApiError
interface ApiError {
  code: string;    // UPPER_SNAKE, e.g. VALIDATION_ERROR, NOT_FOUND, CONFLICT, INTERNAL_ERROR
  message: string; // human-readable
  details?: object | null;
}
```

HTTP status mapping: 400 VALIDATION_ERROR · 404 NOT_FOUND · 409 CONFLICT ·
422 VALIDATION_ERROR (express-style per OpenAPI) · 500 INTERNAL_ERROR.
All error responses include header `x-correlation-id`.

> **Canonical routing (R6 + ADR-005):** `nginx.conf` `location` path now **equals** the
> service's own mount prefix `/api/<svc>/v1/`, and every `proxy_pass` carries **no URI

> `/api/import/`, `/api/sync-folders/`) are preserved in `nginx.conf` as `rewrite … last`
> to the canonical `/api/<svc>/v1` path for backward compatibility.

## 8. Mandatory Implementation Rules (anti-patterns that FAIL the build)

These are non-negotiable. Violating any of them produces a silently broken service
(routes that 404 at runtime while contract tests still pass) — the exact class of bug
that cost a full debugging cycle during the calendar reference impl.

### R1. Fastify route params are `:id`, NEVER `{id}`

- ✅ `app.get("/notes/:id", ...)` — Fastify 5 matches `:id` as a path parameter.
- ❌ `app.get("/notes/{id}", ...)` — Fastify treats `{id}` as a **literal** path segment,
  so every real request `/notes/<uuid>` 404s at runtime.
- OpenAPI uses `{id}` — that is a **contract/URL convention**, NOT a Fastify route path.
  Do not copy `{id}` from the YAML into `routes/index.ts`.
- The contract test (`contracts/test/helper.ts` `hasRoute()` guard) now FAILS the build
  if a strict CRUD route does not match at runtime. This catches the `{id}`→`:id` class of bug.

### R2. One generator owns `routes/index.ts` — do not cross-run them

- `scripts/gen-semantics.mjs <svc>` is the **canonical** route generator. It produces the
  "reference pattern" (CRUD + filters + soft-delete + pagination + events) and is what the
  14 generated services use. Re-run it per-service when the OpenAPI contract or Drizzle schema
  changes.
- `scripts/gen-routes.mjs` is **LEGACY** (produces a thinner stub without filters/soft-delete).
  **Do NOT run it over a service that already has a reference impl** — it overwrites and loses
  business logic. It remains only to bootstrap a brand-new service from scratch.
- `notes`, `tasks`, `calendar` are **hand-written reference impls** — authoritative. Never
  regenerate them with either generator; edit `src/routes/index.ts` directly.

### R3. Timestamps are ISO strings (`mode: "string"`)

- All `timestamp` columns use Drizzle `mode: "string"` (stored as ISO-8601 text, not `Date`).
- Route handlers MUST set timestamps with `new Date().toISOString()`, NOT `new Date()`.
- `new Date()` produces a `Date` object → TypeScript error + wrong wire type.

### R4. Contract-first for ANY new endpoint

- If a feature (e.g. `POST /notes/generate-title`, `PUT /notes/order`, `GET /notes?q=`)
  is not in `contracts/openapi/<svc>.yaml`, ADD it to the contract FIRST, then implement.
- Do not invent non-contract routes (ADR-007 §2 path hierarchy). Internal logic (recurrence
  instance creation, dependency blocking) needs no new endpoint — implement it inside existing
  CRUD handlers.

### R5. Events carry `version` + camelCase `data`

- Publish via `@pmos/event-bus` `EventBus.get().publish(subject, row)` with envelope
  `{ id, type:"pmos.<svc>.<res>.<action>", source, timestamp, version, correlationId, data }`.
- `data` keys are camelCase (`noteId`, `bodyMd`, `taskId`, `oldStatus`). Subject matches
  `contracts/asyncapi/events.yaml`.

### R6. nginx `proxy_pass` — NO trailing slash (gateway rule)

- Internal `location /api/<svc>/` blocks in `platform/docker/nginx.conf` MUST use
  `proxy_pass http://<svc>_up;` **without** a trailing slash.
- ❌ `proxy_pass http://notes_up/;` — nginx matches `location /api/notes/`, strips the
  matched prefix and forwards `/v1/...` instead of `/api/notes/v1/...` → Fastify 404
  (exact bug class from `docs/IMPROVEMENTS.md` §2.2 / E3).
- ✅ `proxy_pass http://notes_up;` — nginx forwards the **original URI** unchanged
  (`/api/notes/v1/health-check`), which the service mounts under `/api/<svc>/v1`.
- The public mirror `location /api/v1/` → `integrations_up` needs the same check: verify
  what URI integrations expects on its public entry.
- After rebuilding any service, restart the gateway (`docker compose up -d --force-recreate
  api-gateway`) — nginx caches upstream IPs at startup (see `docs/TROUBLESHOOTING.md`).
